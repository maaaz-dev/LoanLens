# LoanLens — Active ML Service Integration Handoff (v2.0)

> **Current contract:** This file replaces the original v1 nine-feature / Random Forest / threshold 0.30 handoff. For the active service, use the seven-feature request below and the model metadata actually returned by /model-info.

## Purpose

LoanLens uses a Java 21 / Jakarta Servlet web application and a separate Python FastAPI inference service. The Java application validates the application workflow and calls the Python model API only when LOAN_ML_MODE=http. The Python service loads ml_service/models/best_model.joblib with its preprocessing pipeline and ml_service/models/model_metadata.json.

**Active model metadata in the repository snapshot:** LightGBM, version v2.0, positive class B, negative class G, threshold approximately 0.42. The active runtime's /model-info response is authoritative if the artifact/configuration changes.

## Architecture

~~~mermaid
sequenceDiagram
    actor User
    participant UI as Browser / JSP
    participant Java as Java Servlet + Service
    participant Store as Repository
    participant API as Python FastAPI
    participant Model as Saved LightGBM Pipeline

    User->>UI: Submit synthetic example
    UI->>Java: POST /api/applications
    Java->>Java: Validate application
    Java->>Store: Save application
    Java->>API: POST /predict (HTTP mode only)
    API->>Model: Preprocess and predict
    Model-->>API: Class probabilities
    API-->>Java: Class, probability, threshold, version
    Java->>Store: Save prediction record
    Java-->>UI: Success response
~~~

In mock mode, the Java backend returns a simulated result and the Python service is not the inference source. Do not describe mock output as a real model prediction.

## Active request contract

**Endpoint:** POST http://127.0.0.1:8000/predict  
**Content-Type:** application/json

The API accepts exactly these seven fields (extra fields are rejected):

| Field | Type / constraints |
|---|---|
| INVESTMENT_TOTAL | Finite number greater than zero |
| ACCCURRENTBALANCE | Finite number; negative values allowed |
| INSTALL_SIZE | Finite number greater than or equal to zero |
| DUE_PAYMENT | Finite number greater than or equal to zero |
| COMPENSATION_CHARGED | String from the learned/accepted category set or a supported alias |
| CLIENT_TYPE | String from the learned/accepted category set or a supported alias |
| REPAY_MODE | String from the learned/accepted category set or a supported alias |

INF_GENDER and INF_MARITAL_STATUS are not part of the active model request. The Python Pydantic schema uses extra="forbid" so unknown fields are rejected instead of silently ignored.

### Example request

~~~json
{
  "INVESTMENT_TOTAL": 2000000,
  "ACCCURRENTBALANCE": 100000,
  "INSTALL_SIZE": 10000,
  "DUE_PAYMENT": 0,
  "COMPENSATION_CHARGED": "N",
  "CLIENT_TYPE": "Rural",
  "REPAY_MODE": "N"
}
~~~

### Example response shape

~~~json
{
  "predicted_class": "G",
  "probability_b": 0.21,
  "threshold_used": 0.42,
  "model_version": "v2.0"
}
~~~

Values above illustrate the response schema only; they are not a promised result for a real applicant. The actual response is generated by the active model.

The model compares probability_b with the active threshold to return B or G. The label B is a dataset class and has **not** been independently established as a legal or financial default event.

## Run and verify the Python service

From the repository root in PowerShell:

~~~powershell
py -3.14 -m venv .\ml_service\.venv
& ".\ml_service\.venv\Scripts\python.exe" -m pip install -r ".\ml_service\requirements-runtime.txt"
& ".\ml_service\.venv\Scripts\python.exe" -m unittest discover -s ".\ml_service\tests" -v
.\ml_service\start_service.ps1
~~~

If a compatible environment already exists, reuse it rather than recreating it. Keep the service terminal open. Verify in a second terminal:

~~~powershell
Invoke-RestMethod "http://127.0.0.1:8000/health" | ConvertTo-Json -Depth 5
Invoke-RestMethod "http://127.0.0.1:8000/model-info" | ConvertTo-Json -Depth 8
~~~

Check model_version, selected_model, threshold, and input_features before demoing. Use only synthetic values.

## Error handling

- Python schema/category validation errors return HTTP 422.
- Java application input validation is handled by the Java API; its documented successful create response is 201.
- In HTTP mode, an upstream inference failure is surfaced as a structured Java-side prediction failure (typically HTTP 502), rather than being silently changed into a mock prediction.
- A model response should include a valid class, finite probability between 0 and 1, threshold between 0 and 1, and model version.

## Model evaluation and safe claims

The repository's model_metadata.json describes selection and threshold metrics on its validation split. Those are validation figures, **not** independent external-test performance. Confirm provenance, label meaning and performance on a representative independent holdout before making model-quality claims.

Do not use this academic prototype to approve/reject real loans or make other real lending decisions. A reliable data dictionary, representative independent evaluation, calibration review, fairness/privacy review and live operational validation are all outside the claims made by this handoff.
